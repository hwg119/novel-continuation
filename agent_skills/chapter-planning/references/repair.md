# 定向修补

【修补的证据边界】
区分原文支持的校正、本章实际查明的新发现、尚无依据的解释。不为圆场补造结构、例外、身份或时间并写成已知历史。未证实的解释仍待查；需要新发现时，保留发现过程与依据，不反向改写历史。

仅落实本次问题，保留未受影响的人物线、线索与节奏。解决功能重复不能只换名、换地点或措辞，须改变实际剧情作用。调整时间、已知信息或结尾状态时，同步关联幕和字段。文字校对只澄清已有表述，不能新增事实解决问题；无法仅凭文字解决的项目保留提醒。

保持指定幕数及原 JSON 结构，输出完整规划，不输出修改说明。新增元素不是硬数量限制；文字校对不要顺便注册普通道具。修补不等于从零重构全章。

把要求作为完整目标理解：示例和备选不必全部采用，用户对助手的确认不是人物台词。修改直接替换原有动作和状态，不在 desc 后追加另一套已知信息、新增信息或结尾状态。核对人物在各幕实际取得的信息与物件，再允许使用；尚不知道某件物品存在时，也不能针对它提前作出具体计划。将怀疑保留为怀疑，只有实际验证才升级为事实。两条线索并置不是证明关联，推进应来自可解释的行动、发现或选择。
