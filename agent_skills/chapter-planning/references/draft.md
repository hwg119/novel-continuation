# 起草

title 只含回目，不含章号。幕数配置默认表示上限，按本章实际自然场景数输出即可，不必接近上限；只有用户明确指定固定幕数时才严格遵守。先确定当前已有状态，再安排本幕变化和可供下一幕使用的结束状态。通常聚焦一至两条人物线，需要时可以增加；不重演已经完成的事件，不一次耗尽全部悬念。

time 字段用于说明各幕的相对顺序，默认写自然时间锚点，不为每幕编造日期和钟点。只有精确时间参与证据、期限、预约或用户明确指定时才保留；连续场景可写“随后”“同日晚些时候”，不要形成逐幕报时的日志感。

只输出完整 JSON：
{"title":"回目","beats":[{"num":"一","name":"幕名","beat_type":"dramatic / reaction / transition / atmosphere / setup / payoff","pov":"视角人物","time":"相对时间","location":"地点","thread":"推进的故事线","goal":"人物在本幕的即时意图；过渡或气氛幕可为空","obstacle":"本幕实际阻力；没有则为空","choice":"本幕有分量的选择；没有则为空","cost":"本幕实际发生或明确承担的代价；没有则为空","change":"本幕产生的变化；仅连接场景时可为空","known_before":["已知信息"],"new_facts":["本幕新信息"],"new_elements":[{"name":"主要新增元素","type":"类别","source_or_entry":"进入剧情的过程","future_use":"后续用途"}],"desc":"具体场景、互动与感官动作","end_state":"结束状态及未完成线索"}]}

没有主要新增元素则 new_elements 为 []。不输出思考、解释或 Markdown。

规划是供后续写作使用的结构提纲，不是正文。每幕保持紧凑：desc 建议不超过 220 个汉字，known_before 与 new_facts 各最多 3 条且每条只写一个事实，new_elements 只登记会持续影响后文的主要新增元素（通常 0 至 1 个）。

先保证整章形成一条完整弧线：人物欲望受到有效压力，至少出现一次有分量的选择或不可回避的行动，并在章末形成可感后果。dramatic / payoff 幕应具体写出适用的 goal、obstacle、choice、cost、change；reaction / transition / atmosphere / setup 幕只填写真实存在的项目，其余使用空字符串，不得为了字段齐全伪造危机、代价或状态变化。安静场景可以只蓄积情绪、改变人物距离、建立气氛或连接时空，但必须服务整章节奏。

如果输入中提供了连续叙事梗概，分幕是从已形成的故事中提取自然场景，而不是重新按要求清单分配场景。幕表示存在离场、明显时间跳跃或主要互动关系转换的自然场景，不表示场景内部的发现、争执、决定和执行节拍。同一地点、同一主要冲突及同一决定从形成到执行通常属于一幕；相邻内容合并后没有损失独立变化时必须合并。幕数是结果，上限不是目标；宁可少一幕，也不新增重复抄件、编号错误、小故障、新文件或新谜团凑数。配角优先通过拒绝背书、撤回支持、提出不同选择或造成关系后果发挥作用。

如果输入已经标出“场景源”，场景边界已经由上一步确定：严格一份场景源对应一幕，保持顺序，只提取结构字段；不得再次拆分、合并、新增场景或按字段重新设计剧情。审查认为边界有问题时应退回场景化梗概重写，而不是在结构化结果上增减幕。

不要让连续场景都采用核对材料、听取汇报、解释制度、签字确认等同一种互动机制。结构字段不能代替戏剧化呈现：人物摩擦要发生在具体言行中，代价要在事件后果中被感到。避免在多个字段重复叙述同一事件；优先确保所有指定幕和完整 JSON 均能输出。
