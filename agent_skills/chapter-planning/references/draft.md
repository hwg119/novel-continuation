# 起草

title 只含回目，不含章号。幕数若给出允许范围，应按本章实际事件密度在范围内选择，不为凑数拆分同一事件；只有明确指定固定幕数时才严格遵守。先确定当前已有状态，再安排本幕变化和可供下一幕使用的结束状态。通常聚焦一至两条人物线，需要时可以增加；不重演已经完成的事件，不一次耗尽全部悬念。

time 字段用于说明各幕的相对顺序，默认写自然时间锚点，不为每幕编造日期和钟点。只有精确时间参与证据、期限、预约或用户明确指定时才保留；连续场景可写“随后”“同日晚些时候”，不要形成逐幕报时的日志感。

只输出完整 JSON：
{"title":"回目","beats":[{"num":"一","name":"幕名","pov":"视角人物","time":"相对时间","location":"地点","thread":"推进的故事线","goal":"人物本幕想取得什么","obstacle":"实际阻力","choice":"人物作出的选择","cost":"选择的代价或风险","change":"本幕后信息、决定、关系或局面的实际变化","known_before":["已知信息"],"new_facts":["本幕新信息"],"new_elements":[{"name":"主要新增元素","type":"类别","source_or_entry":"进入剧情的过程","future_use":"后续用途"}],"desc":"具体事件与人物选择","end_state":"结束状态及未完成线索"}]}

没有主要新增元素则 new_elements 为 []。不输出思考、解释或 Markdown。

规划是供后续写作使用的结构提纲，不是正文。每幕保持紧凑：desc 建议不超过 220 个汉字，known_before 与 new_facts 各最多 3 条且每条只写一个事实，new_elements 只登记会持续影响后文的主要新增元素（通常 0 至 1 个）。goal、obstacle、choice、cost、change 写实际剧情功能，不能用“继续调查、获得线索、留待核实”等空泛措辞代替；安静场景的 change 可以是关系、态度或决定。避免在多个字段重复叙述同一事件；优先确保所有指定幕和完整 JSON 均能输出。
