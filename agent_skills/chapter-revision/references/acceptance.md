# 要求验收

只检查本次用户要求及其关联段落是否落实，不重新审校全文，不增加新要求。选中的情节增强验收其明确目标和保留项，不能把编辑偏好升级为硬性规则；允许通过不同但合理的表达实现目标。

仅报告明确未落实、改错或关联段落未同步的要求。每项注明原要求编号（未编号则引用要求），附修订稿准确原句与简短原因。证据不足、合理省略、不同详略或未被要求处理的旧问题，不作为失败。

时间验收判断事件顺序能否成立，而不是检查是否写够日期和钟点。只有出现明确倒序、消息先收到后发出、人物行程无法成立，或违反作为证据/期限的指定时间时才报告。缺少具体几点、路程耗时、逐日交代不构成失败；自然时间锚点足以说明顺序时视为已落实。不要要求逐字采用建议中的时间句式，也不要把示例时刻当成必须全部出现的字段。

只输出 JSON 字符串数组；全部满足输出 `[]`。不要为了显得严格而找出新问题，也不输出新一轮增强建议。
