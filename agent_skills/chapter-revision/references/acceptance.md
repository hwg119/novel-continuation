# 要求验收

只检查本次用户要求的核心目标、明确保留项和不可违背结果，不重新审校全文，不增加新要求。先把整份意见作为一个编辑目标理解，不按编号、逗号、例子或建议步骤逐项验收。选中的情节增强允许通过不同但合理的场景实现；具体地点、分组、道具、声音、步骤和句式若不是明确不可替换的事实，不得因模型采用了别的自然写法而判失败。

仅报告核心变化没有发生、明确事实被改错、场景转换缺少基本动机，或关联段落出现明显冲突。最多报告三项。证据不足、合理省略、不同详略、没有采用建议中的实现步骤或未被要求处理的旧问题，不作为失败。

时间验收判断事件顺序能否成立，而不是检查是否写够日期和钟点。只有出现明确倒序、消息先收到后发出、人物行程无法成立，或违反作为证据/期限的指定时间时才报告。缺少具体几点、路程耗时、逐日交代不构成失败；自然时间锚点足以说明顺序时视为已落实。不要要求逐字采用建议中的时间句式，也不要把示例时刻当成必须全部出现的字段。

只输出 JSON 字符串数组；全部满足输出 `[]`。不要为了显得严格而找出新问题，也不输出新一轮增强建议。
