# 小说续写工作台

> 面向长篇小说的本地 AI 写作工作台：记住前文、管理设定、规划后续，让每次修改都可核对、可回退。

小说续写工作台不是一个只有“生成下一段”的聊天框。它围绕长篇创作提供正文管理、分幕规划、小说 Wiki、历史查证、人物关系、故事审校和可比较修订；一本书对应一个本机工程目录，正文、设定和运行记录默认留在你的电脑上。

![工作台首页：演示工程概览](assets/screenshots/home.png)

## 为什么使用它

- **长篇记忆有依据**：从原文整理 Wiki，人物状态和关系都能回到章节引文。
- **先规划，再续写**：分幕规划会按需查阅历史正文，信息不足时保留疑问而不是编造答案。
- **修改不覆盖原稿**：候选稿可以逐段比较、编辑和验收，确认后才应用到正文。
- **本地优先**：小说工程、密钥和日志保存在本机；支持云端模型，也支持 Ollama。
- **完整创作工作流**：从母本导入、续写、审校、润色到插图和 Word 导出集中在一个界面。
- **对话创作入口**：自然语言发起查看、分幕、续写、故事审校和修订，也可询问项目功能并跳转到对应页面。会话与实时输出保存在本机，支持刷新恢复、重命名和删除，正文仍在阅读页展示。

### 对话创作

说出目标即可讨论情节、规划分幕、续写或修订；也可以询问工作台的使用方法，通过回复中的按钮打开对应功能页。处理日志在对话内折叠展示，会话可刷新恢复、重命名和删除，候选稿仍需确认后应用。

讨论故事时，助手可按需翻读章节正文、已保存摘要，搜索历史片段或查阅 Wiki，再结合证据回答。查阅有预算上限，来源与过程保存在会话日志中；读取资料不会自动修改正文或重新编纂 Wiki。

对话助手可从专业技能目录按需加载规划、写作、审校和修订方法；分幕讨论与修订验收共用核心评价规则。技能加载名称、模式和版本写入日志，加载只读取规则，不启动创作任务或改写作品。

对话输入优先提供当前工作稿、用户要求和相关正文，历史任务中的整份稿件只保留版本索引。旧助手意见不默认进入评估，需要承接此前建议时可按需查阅该轮对话；历史记录和作品版本仍完整保存在本地。

对话上下文使用统一的“作品对象”层：分幕、正文候选、审校结果和当前插图都有类型、ID、内容指纹、状态与来源。模型可通过 `list_artifacts` / `read_artifact` 列出、分页读取对象，并结合对话选择目标；程序核验目标归属和类型，不用标题正则替代意图判断。同一会话、章节按对象类型记住当前工作版本，刷新或重启后仍可继续；分幕修订与正文修订共用目标选择和输入快照，候选不会因未保存而自动退回旧稿。正文应用仍核对保存稿，避免覆盖手动修改。

作品对象层借鉴 [Open Canvas 的版本设计](https://github.com/langchain-ai/open-canvas/blob/main/packages/shared/src/types.ts)，复用本项目的 SQLite 会话与任务文件。Open Canvas 已归档，仅作为设计参考；对话调度正式使用 [Deep Agents](https://github.com/langchain-ai/deepagents)。审校、插图已接入对象查阅，业务执行仍沿用现有接口。

#### Deep Agents 对话引擎

默认使用 Deep Agents 的原生工具调用循环，负责判断下一步、按需查阅、选择作品对象和提出操作；生成任务、确认应用、文件保存及冲突保护仍由本项目执行。依赖已纳入根目录 `requirements.txt`，无需额外试验环境或启用开关。工作进程使用后端相同的 Python 环境，独立进程用于可靠停止本轮回复。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe web_main.py
```

需要 Python 3.11+。对话使用 Deep Agents 理解上下文并按需调用工具。当前支持 OpenAI 兼容及 DeepSeek 原生工具调用，沿用所选地址与密钥并统一规范 API 地址，DeepSeek 关闭思考；其他供应商特殊接口尚未适配时会明确提示。可通过 `NOVEL_DEEPAGENTS_PYTHON` 指定调试用解释器。

引擎关闭子智能体与内置文件工具，只开放作品查阅、历史证据读取和操作提案，不开放主机命令或直接改写小说。每轮最多6次模型调用、6次资料查阅及32000字证据，过程实时显示在聊天日志中，最终回复当前按整条返回。对话模型负责理解上下文、承接建议并整理具体操作要求，执行与验收使用同一份要求，原始聊天保留作追溯而不覆盖要求。完整模型输入、返回、工具请求、结果和耗时保存在工程 `runs/plan_logs/deepagents_*.jsonl`，密钥脱敏，不启用外部 LangSmith 追踪。

小样本评估（会调用所选模型，但只使用合成资料，不执行生成或保存小说）：

```powershell
python tools/deepagents/evaluate.py --live --model-config deepseek-flash
```

结果及完整日志保存在 `workspace/agent_trials/`；模型判断效果应与协议回归测试区分，不以框架接通代替质量验收。

### 质量回归基线

`tools/deepagents/fixtures/story_audit_cases.json` 是小而固定的故事审校基线：覆盖跨章时间线、人物知情边界、弱线索不过度升级，以及避免重复情节增强。每个用例都记录预期、是否应产生修订要求和仅用于初筛的文字信号；信号检查不能替代人工编辑判断。

```powershell
# 不调用模型：校验用例和输入/输出协议
python tools/evaluate_story_audit.py --validate
python tools/verify_quality_regression.py

# 明确许可后才会把合成文本发送给所选模型；结果与完整日志保存在 workspace/agent_trials/
python tools/evaluate_story_audit.py --live --model-config deepseek-flash
```

离线检查覆盖：新建规划不得混入旧分幕、修订不能把仅改幕名误判为内容修改，以及故事审校实际收到的当前章与前章证据。后续新增模型能力前，应先增加一个能失败的合成案例，再修改 Skill 或流程。

两次合成审校后，可离线比较用例覆盖、模型、Skill 版本、输入指纹、输入长度、模型调用数、耗时和初筛结果；比较工具不读取真实小说工程，也不展示原始提示词：

```powershell
python tools/compare_quality_runs.py workspace/agent_trials/story_audit_旧批次 workspace/agent_trials/story_audit_新批次
```

输出中的“元数据一致”不等于故事质量相同；它只说明没有可见的输入或配置变化，完整小说判断仍需查看两侧日志与人工结论。

生成结果按类型显示操作卡片：分幕可预览并保存，正文可直接阅读，审校可导入修订要求，修订稿可查看、比较并进入应用流程。版本入口定位到对应任务，不自动应用候选稿。

对话也可生成章节 SVG 插图，沿用工程画风和现有插图流程，在聊天中查看进度与图片。已有正文或分幕时提供快捷入口，保存后的插图用于正文展示与 Word 导出。

聊天中的修订稿可直接打开差异弹窗，核对后“应用并保存正文”，自动备份原稿并沿用章节保存与向量更新流程；原稿已变化或存在验收问题时不会直接覆盖。

聊天回复停止与后台任务取消分开处理。规划、分幕修订、正文修订和故事审校可请求安全取消，等待当前调用返回后停止；任务阶段、耗时和取消状态同步到聊天与控制台。规划和正文修订有有效检查点时可继续，恢复沿用原模型并核验输入。母本导入、向量写入及其他文件生成任务暂不开放取消。

## 快速体验

需要预先安装 Python 3.11+ 和 Node.js 20+。启动器会自动创建虚拟环境、安装缺失依赖、构建前端、检查端口并打开浏览器。

### Windows

克隆或下载项目后双击 `start.bat`。也可以在 PowerShell 中运行：

```powershell
.\start.ps1
```

仅检查环境而不安装或启动：`.\start.ps1 -Check`。

### macOS

首次使用先在终端赋予执行权限，之后可以双击 `start.command`：

```bash
chmod +x start.command start.sh
./start.command
```

也可以始终通过 `bash start.sh` 启动；仅检查环境可运行 `bash start.sh --check`。

### 手动启动

如需完全手动管理环境，在 PowerShell 中运行：

```powershell
git clone https://github.com/hwg119/novel-continuation.git
cd novel-continuation
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
npm install --prefix frontend
npm run build --prefix frontend
python web_main.py
```

打开 <http://127.0.0.1:8765>。想先浏览而不调用模型，可在“工程与母本 → 导入已有工程”中选择 `examples/demo-project`；原创演示小说《雾港来信》已经包含 5 章正文、下一章规划、Wiki 事实、人物关系和章节插图。

> 调用续写、规划、审校、Wiki 自动编纂和插图生成需要配置模型。浏览、编辑、全文搜索和查看演示数据不需要模型。

## 开发与手动维护

服务仅绑定 `127.0.0.1`。修改 Python 后重启 `web_main.py`；修改前端后重新运行 `npm run build --prefix frontend` 并刷新浏览器。开发前端时可运行 `npm run dev --prefix frontend`，Vite 会把 `/api` 请求转发到 Python 服务。

已有工程可以直接导入，不需要转换工程文件。

## Web 页面与流程

- **对话创作**：以自然语言讨论并发起创作任务，查看过程与结果，或跳转到对应功能页；与原有功能工作台并行使用。
- **首页**：汇总工程状态、最近章节、Wiki 待办和运行记录，并提供下一章续写入口。
- **小说正文**：按章节浏览、阅读和编辑正文，查看插图与摘要，搜索全书内容，生成分级英语学习版，比较修订稿并导出 Word。
- **续写与分幕**：维护全书规则、当前章规划和分幕大纲；支持模型提取、按问题修改以及续写生成。
- **审校与修订**：整体评估故事连续性和重大主线逻辑，提供可选情节增强，并生成可比较、可编辑、可回看的修订稿。
- **小说 Wiki**：从原文增量整理人物、事物、经历、状态和关系证据，为续写与审校提供可追溯参考。
- **人物关系图**：以人物和原文关系记录构建交互图谱，可按人物与章节范围查看关系变化。
- **工程与母本**：新建或导入工程、导入母本、管理章节范围和向量库。
- **运行记录**：按时间查看后台任务、生成过程、模型回复和错误信息；底部控制台同步显示当前任务进度。
- **开发者地图（默认关闭）**：只读浏览分幕、续写、审校与修订的核心数据流。仅当本机 `config.json` 设置 `"developer_map_enabled": true` 并重启服务后才注册接口和显示导航。点击节点查看上下游、输入材料的来源与组成、代码入口及 Skill / 提示词组装源码；源码附带行号和文件指纹。运行回放读取当前工程 `runs/plan_logs`，按事件查看实际输入、模型返回、工具和验收记录，不触发模型调用。质量回归页则只使用固定的合成审校用例：明确点击短/长上下文评测才会调用选定模型，产物独立保存在 `workspace/agent_trials`，可对比模型、Skill 版本、输入指纹、耗时及初筛结果，绝不读取或发送小说章节。地图是人工维护的设计索引，不是动态调用图；导入、Wiki、学习版和插图尚未展开。日志详情须主动展开，已配置密钥及常见凭证会隐藏，但小说和个人内容仍需在分享前人工检查。
- **全局配置**：管理并排序大模型配置，选择默认续写模型和当前向量模型，以及维护代理、工作目录等跨工程设置。

各页面有独立 URL，章节相关地址包含工程 ID 和章号；刷新或使用浏览器前进、后退不会默认跳回首页。

修订流程使用 LangGraph 管理生成、检查与验收，支持查看运行记录和从检查点恢复。候选稿不会自动覆盖正文，仍需用户比较、确认并保存。

故事审校区分“主线修订”与“情节增强”：关注影响故事成立与后续发展的重大问题，忽略不影响故事的局部细节；增强意见由用户选择后导入，不强制扩写。历史记录保留依据和增强意见，旧版一致性记录仍可查看。

修订默认一次生成必要段落的局部补丁，保护其他正文；增删段落或大幅调整情节、文风时可切换整章重写。只执行用户填写或导入的要求，验收不另行增加新建议。补丁和验收结果均可在完整修订日志回看，候选稿仍需确认后应用。

分幕、续写、故事审校、执行修订的方法分别维护在 `agent_skills/chapter-planning`、`chapter-writing`、`story-audit` 和 `chapter-revision`。运行器按用途加载 Skill 与当前步骤的参考，日志记录版本、请求、回复及核验结果；上下文检索、保存与恢复由项目运行时统一管理。默认整体审校一次，仅在重要历史疑问需要依据时按需查证，不默认提取全文断言并逐个判定疑点。

“修订方式”中的可选表达润色使用 `agent_skills/prose-polish`，处理泛化描写、重复解释与同质化对白，保留剧情事实、线索和人物声音。它不判断作者来源，不自动在续写或修订后调用；润色稿仍需比较、确认应用并保存。修订稿须先应用到正文编辑器，才能针对它润色。

回目与分幕规划使用 LangGraph 保存各阶段检查点。规划审查试点支持模型按需搜索历史正文、打开章节片段，再依据证据给出结论；信息足够时直接结束，不强制查阅。查阅轮数有上限，完整请求、返回证据、来源位置、决策及耗时保存在工程规划日志中，便于复盘效果与成本。当前主动搜索采用关键词，不依赖向量库。失败或中断后，可在运行记录中确认原模型并继续；已完成阶段无需重新调用。工程设定、历史正文或摘要变化后须重新规划。恢复完成的规划可在运行记录中确认保存到对应章节的续写设定，旧任务没有检查点时须重新生成。

历史查证方法独立维护在 `agent_skills/history-research/SKILL.md`，由项目运行器加载，不依赖 Codex 技能环境。技能脚本提供去重搜索、章节阅读和引文定位，供规划审查与故事审校按需使用。日志记录 Skill 版本，未查清的重要疑问保存为提醒，不自动修改情节。

规划审查员可按需委托单问题查证员。查证员仅接收具体疑问与相关证据，自主搜索或翻读历史后返回事实结论，不评价或改写整章；审查员再决定是否采纳。委托及查阅都有预算，信息充分时不增加调用。日志区分整章审查与单问题查证，记录问题、输入来源、查阅证据、结论和采纳情况；查证失败保留未知提醒，不让整个规划失败。

规划硬校验只负责可解析、回目及有效分幕内容、指定分幕数量和字段类型。视角数量、新增元素数量及辅助信息完整度属于创作建议，不阻止生成。可选文字规范失败时保留此前有效版本，已通过剧情验收的稿件不会因可选修补失败而丢失；提醒仍保留供核对。

“按问题修改分幕”会对比实际变化，再围绕用户要求验收；只改回目或幕名不视为完成情节类修改。未落实时最多定向补修一次，页面区分通过、未落实和验收未完成，并保留对应日志。候选规划不会自动覆盖已保存版本，确认后需保存设定。

## 插图与 Word 导出

每章可以根据正文和章节规划生成独立的 SVG 插图，并在页面中预览或重新生成。插图会随当前章一起导出到 Word；没有插图时仅导出标题和正文。Word 使用适合中文阅读的排版，并包含章号和页码。

插图生成需要可用的大模型配置，Word 导出本身不会调用模型。

插图采用自由 SVG 意象图，由模型依据本章设计原创构图，不依赖素材库，支持路径、曲线、渐变和空间层次。保存前经过静态校验与 resvg 渲染，失败保留当前插图，最多生成两次。正文、插图预览与 Word 使用相同渲染器，自由绘制过程保留完整日志。

resvg 依赖随 `npm install --prefix frontend` 安装；后端渲染时需要 Node.js 在 PATH 中，无需新增常驻服务。依赖缺失会在调用模型前提示安装，插图预览及带插图的 Word 导出也需要该依赖。

## 工程数据与持久化

```text
workspace/
  projects.json                    工程索引
  <小说工程>/
    project.json                   本书设定与分章规划
    chapters/chapter_N.txt         母本与续写章节
    vectorstore/                   FAISS 向量索引及 SQLite 元数据
    wiki/chapters/chapter_N.json   按章提取的 Wiki 事实与正文哈希
    learning_editions/             与正文隔离的分级英语学习版
    illustrations/chapter_N.svg    已生成的本章插图（可选）
    exports/chapter_N.docx         Word 导出文件
    runs/web_jobs/                 Web 后台任务状态和日志
    runs/revisions/                章节旧稿快照
```

`config.json` 保存全局模型等配置，包含密钥；`workspace/` 保存用户小说。这两者已加入 `.gitignore`。章节保存会检查文件版本，避免覆盖另一浏览器窗口中的修改；实际保存时会留下旧稿快照。耗时任务在后台运行，服务重启后未完成的任务标记为“已中断”。

## 可选的本地模型

- **Ollama 大模型**：在“全局配置 → 大模型配置”选择 `Ollama`，填写 Base URL（例如 `http://localhost:11434/v1`）和模型名。续写调用 Ollama 原生 `/api/chat`。
- **本地 BGE-M3 Embedding**：运行 `python tools/embedding/dl_bge_m3.py` 下载模型，再运行 `python tools/embedding/embedding_server.py`。向量配置可指向默认的 `http://127.0.0.1:11435`。没有模型时可用“离线哈希”验证流程，但检索质量较低。

## 验证

### 可选模型追踪（Phoenix）

默认关闭，不影响原有 `requirements.txt`。只想使用小说工作台，无需安装任何追踪依赖。

Phoenix 查看服务与小说程序分开安装：

```powershell
python -m venv .venv-phoenix
.\.venv-phoenix\Scripts\python.exe -m pip install -r tools/observability/requirements-phoenix.txt
.\tools\observability\start-phoenix.ps1
```

服务页面为 `http://127.0.0.1:6006`，数据保存在 `workspace/phoenix`，启动脚本关闭平台遥测，HTTP 页面仅监听本机。Phoenix 另有默认的 gRPC 接收端口 4317（此版本监听所有地址）；本项目仅使用 HTTP 上报，不要将这两个端口开放到公网。

在小说项目原有虚拟环境中，仅安装采集端可选依赖，然后在启动工作台的同一终端启用：

```powershell
.\.venv\Scripts\python.exe -m pip install -r tools/observability/requirements-tracing.txt
$env:NOVEL_TRACE_ENABLED = '1'
$env:NOVEL_TRACE_ENDPOINT = 'http://127.0.0.1:6006/v1/traces'
.\.venv\Scripts\python.exe web_main.py
```

关闭方式：将 `NOVEL_TRACE_ENABLED` 设为 `0` 并重启工作台。依赖缺失时会警告并降级；上报在后台执行，失败不阻断生成，原有 JSONL 日志保留。

当前追踪统一模型调用及分幕生成/修订，记录提示词、原始输出、调用参数、异常、工作流阶段和审计事件。启用后小说文本会发送到配置的追踪地址，请不要未经确认配置外部服务；密钥字段及模型配置中的密钥值会脱敏。每条输入/输出默认最多记录 200000 字符，超出时标注截断，可通过 `NOVEL_TRACE_MAX_CHARS` 调整；`NOVEL_TRACE_PROJECT` 可指定 Phoenix 中的项目名。
